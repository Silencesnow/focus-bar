# Focus Bar 任务状态耗时统计设计

## 目标

将统计口径从“前台应用停留时间”改为“任务状态时间线”，回答三个问题：

1. 今天所有任务一共执行了多久；
2. 今天至少有一个任务在执行的真实墙钟时间有多久；
3. 每个任务分别执行了多久、被中断了多久、经历了多少轮执行。

## 状态语义

Focus Bar 已经将 cmux 与 Codex 统一映射为四种状态。本统计只使用其中两类：

- `executing`：绿色，计入任务执行时间；
- `needs_action` / `needs_review`：红色，视为等待响应，开始一个候选中断区间；
- `idle`：灰色，不计入执行时间，但不会主动结束已经开始的候选中断区间。

一个中断区间从任务第一次变红开始，到同一任务下一次变绿结束。红色后可以短暂经过灰色。若查询范围结束前没有再次变绿，该开放中断区间舍弃，不计入统计。

执行区间从任务变绿开始，在它变为任意非绿色状态时结束。当前仍为绿色的区间统计到最近一次可靠采样时间。

## 汇总口径

总览同时展示两个不可互换的指标：

- **任务执行量**：所有任务执行区间时长直接相加。并行执行会分别计入，三个任务同时运行 30 分钟得到 90 分钟；
- **实际运行覆盖**：合并所有任务执行区间后计算并集。三个任务同时运行 30 分钟得到 30 分钟。

每个任务展示：

- 执行总时长；
- 已闭合中断总时长；
- 执行轮次；
- 已闭合中断次数。

统计范围继续支持“今天”和“最近 7 天”。跨越范围边界的已知区间按范围裁剪。开放中断永远不计入。

## 数据采集

前端在完成 cmux 与 Codex 合并和状态判定后，将当前任务的 `task_id`、标题、来源、状态及采样时间发送给 Rust。这样统计与工具条展示使用同一个状态结果，不再重复推断。

Rust 将连续的相同任务状态合并为持久化状态区间，保存 `started_at` 与 `last_seen_at`。采样之间若超过可靠间隔，后一次采样开启新区间；不会把应用休眠、退出或数据源失联期间补算成执行时间或中断时间。

某个数据源读取失败时，前端不提交该来源的新样本；现有区间停在最后一次可靠采样。任务从成功快照消失时，同样不会无限延长旧区间。

旧的 `activity_segments` 数据保留，不删除，但新版统计窗口不再使用前台应用、键盘输入、浏览器和 VS Code 停留片段。旧采集循环停止启动，避免继续产生无用数据和辅助功能探测开销。

## 存储与聚合

SQLite 新增任务状态区间表，和旧表分开，避免迁移或破坏历史数据。聚合过程：

1. 读取与查询范围相交的状态区间；
2. 按任务排序并形成绿色执行区间；
3. 将红色起点与同一任务后续第一个绿色起点配对，形成已闭合中断区间；
4. 裁剪到查询范围；
5. 分别计算每任务总计、所有任务执行量和执行区间并集。

状态区间保留任务标题快照；展示时若当前配置仍存在，则用最新名称覆盖历史标题。

## 界面

统计窗口改为：

- 顶部两张总览卡：任务执行量、实际运行覆盖；
- 任务列表：任务名、执行时长、中断时长、执行轮次、中断次数；
- 保留今天 / 最近 7 天切换；
- 移除活动类型、来源、归属可信度等旧口径模块。

没有任何绿色执行区间时显示空状态。只有开放红色区间时仍显示空状态，因为该数据尚不可闭合。

## 测试与验证

核心测试覆盖：

- 绿色到非绿色形成执行区间；
- 红色经过灰色后再次变绿形成中断区间；
- 没有后续绿色的红色区间被舍弃；
- 多任务并行时任务执行量相加、实际运行覆盖去重；
- 跨日期范围正确裁剪；
- 采样断档不补算时间；
- cmux 与 Codex 使用相同聚合规则；
- 新统计窗口渲染两个总计及每任务指标。

完成后运行 TypeScript 全量检查、Rust 测试、Tauri release 构建，并安装重启应用进行实际界面验证。
