# Focus Bar 非活跃任务折叠设计

## 目标

Focus Bar 主列表只突出今天仍与用户有关的任务，避免长期打开但当天没有互动的会话持续占用空间。较早的空闲任务收进一个可展开区域，仍可随时查看和跳转。

## 已确认的产品规则

- 红色“待处理”和绿色“执行中”始终留在主列表，不因活动时间较早而折叠。
- 灰色“空闲”任务如果今天没有 AI 或终端活动，归入“较早任务（N）”。
- “今天”按用户本地时区的当天零点计算。
- 点击“较早任务（N）”展开或收起；默认收起。
- 展开后的任务卡片保留现有点击、右键菜单及 cmux、Codex、VS Code、Chrome 工具按钮行为。
- 较早任务重新执行、收到待处理事件或产生今天的新活动后，自动回到主列表。

## 方案选择

采用展示层分组：保留现有 cmux 和 Codex 数据采集、状态计算及配置持久化，只在渲染前根据任务状态和 `activityAt` 将 `mergedTasks` 分成当前任务与较早任务。

不采用以下方案：

- 删除或隐藏旧配置：会丢失导航、备注和图标配置，并且无法快速恢复任务。
- 按固定天数清理 cmux workspace：属于外部状态变更，超出 Focus Bar 的展示职责。
- 单独维护归档数据库：当前需求只需要临时折叠，新增持久化模型没有必要。

## 活跃判定

任务满足任一条件时进入主列表：

1. 状态为 `needs_action`、`needs_review` 或 `executing`；
2. `activityAt` 是本地当天零点之后的有效时间；
3. 缺少可靠活动时间，但任务不是灰色空闲。

只有状态为 `idle`，且 `activityAt` 缺失或早于本地当天零点，才进入较早任务区域。缺少时间的空闲任务按较早任务处理，避免未知历史 workspace 持续撑长主列表。

## 展示与交互

主列表先渲染当前任务。存在较早任务时，在其后渲染一行“较早任务（N）”折叠按钮：

- 收起状态只显示数量和展开指示；
- 展开后在按钮下渲染较早任务卡片；
- 展开状态仅保存在当前 Focus Bar 进程内，应用重启后恢复默认收起；
- 数据刷新时，如果任务从较早任务转为当前任务，它立即移出折叠区；
- 折叠按钮不参与任务跳转和右键菜单。

建议文案和图标保持克制，不新增独立归档页面。

## 数据流

1. cmux 与 Codex snapshot 继续生成完整 `mergedTasks`。
2. 纯函数根据当前时间把任务划分为 `current` 和 `inactive` 两组。
3. 建议文案和待处理任务选择仍基于完整任务集合，避免折叠任务漏掉状态变化。
4. 渲染层为任务卡片写入稳定任务 ID，不再依赖分组后的数组位置反查任务，避免展开、收起或刷新造成点击错位。
5. 点击较早任务卡片时仍走现有 `jumpSmart`；成功跳转后的 `last_viewed_at` 更新逻辑保持不变。

## 错误与边界

- 无效 `activityAt` 按缺失时间处理。
- 跨午夜后，上一天的空闲任务在下一次定时刷新时进入折叠区。
- 红色或绿色任务即使没有活动时间也不折叠。
- 当前任务为空但存在较早任务时，主区域显示折叠入口，不显示“当前没有可显示的任务”。
- 数据源报错且正在展示旧快照时，沿用现有 stale 样式，不改变分组结果。

## 测试与验收

### 单元测试

- 本地当天有活动的空闲任务留在主列表；
- 昨天活动或缺少活动时间的空闲任务进入较早任务；
- 红色和绿色任务始终留在主列表；
- 无效时间按较早任务处理；
- 本地午夜边界判定正确。

### 渲染测试

- 存在较早任务时显示数量正确的折叠按钮；
- 默认不渲染较早任务卡片，展开后渲染；
- 展开后的卡片通过稳定任务 ID 找到正确任务；
- 折叠任务重新活跃后自动回到主列表。

### 手工验收

- 打开包含多个历史 cmux/Codex 会话的 Focus Bar，确认主列表明显变短；
- 展开“较早任务”并点击其中一个任务，确认跳转目标正确；
- 在较早任务中发起新一轮 AI 交互，确认该任务自动回到主列表；
- 跨午夜或修改系统日期后刷新，确认分组随本地日期变化。

## 第一版范围外

- 手动归档、置顶或永久隐藏；
- 自定义“活跃天数”阈值；
- 删除 cmux workspace、Codex task 或 Focus Bar 配置；
- 在配置窗口管理归档任务。
