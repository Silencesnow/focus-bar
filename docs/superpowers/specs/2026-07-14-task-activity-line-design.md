# 任务执行动态单行展示设计

## 目标

在每个 Focus Bar 任务卡片中增加一行始终可见的执行动态，让用户无需跳转即可判断任务当前状态、最近在做什么以及最近活动时间，同时保持现有工具条高度与交互方式不变。

## 展示形式

新增行位于目录/端口信息与跳转按钮之间，格式为：

`执行中 · 正在修改 navigation.rs · 2分钟前`

- 状态使用现有四种中文标签：需要处理、待检查、执行中、空闲。
- 摘要优先使用 cmux workspace 的 `latest_conversation_message`；为空时使用最新通知摘要；仍为空时使用已有状态原因。
- 时间取最近一次提交时间与最近一条通知时间中的较新值。
- 整行只显示一行，超出卡片宽度时省略；原始完整文本通过 `title` 提示提供。
- 没有摘要或时间时省略对应片段，不显示空占位符。

## 数据与刷新

只使用现有 `CmuxSnapshot` 已包含的 workspace 和 notification 字段，不新增 cmux 命令、文件读取或定时器。相对时间随现有 cmux 事件刷新以及 30 秒兜底刷新更新。

视图模型负责生成结构化的活动摘要和活动时间，渲染层只负责格式化相对时间、HTML 转义与单行展示。这样数据选择规则可以独立测试，样式也不会与 cmux 数据判断耦合。

## 布局与交互

- 保留标题、目录、端口、cmux/VS Code/Chrome 跳转按钮。
- 新增行使用弱于标题、强于目录的文字层级，不改变状态色含义。
- 工具条总高度保持不变；任务卡片内部使用现有可用纵向空间容纳一行。
- 新增文本不接管点击事件，点击卡片和各跳转按钮的行为保持不变。

## 异常与兼容

- 无法解析时间时只隐藏相对时间，不影响卡片渲染。
- 摘要中的 HTML 特殊字符必须转义。
- 历史任务字段缺失时沿用现有降级逻辑。

## 验证

- 单元测试覆盖摘要优先级、最新活动时间选择、缺失字段以及无效时间。
- 渲染测试覆盖状态、摘要、相对时间和 HTML 转义。
- 运行前端构建与完整测试，并确认 Rust 测试和编译不受影响。
- 在运行中的开发版中检查单行省略、完整悬停提示和现有跳转交互。
